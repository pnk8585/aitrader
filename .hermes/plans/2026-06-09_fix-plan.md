## Bug 1: Timezone Mismatch — Shared Daily Buy Limit

**Objective:** Fix the shared daily buy limit query to use UTC timezone consistently

**Root cause:** `DATE(timestamp) = CURRENT_DATE` uses PostgreSQL's local timezone, but the bots operate in UTC context. If DB timezone != UTC, the daily limit boundary drifts.

### Task 1.1: Fix kraken_pullback.py shared buy limit query

**File:** `/home/pank/projects/aitrader/traders/crypto_trades/kraken_pullback.py`

**Find the shared buy limit block** (search for `AND DATE(timestamp) = CURRENT_DATE`):

**OLD code (around line 618):**
```python
        cur.execute(
            "SELECT COUNT(*) FROM trade_log "
            "WHERE exchange LIKE 'kraken%%' AND action='BUY' "
            "AND DATE(timestamp) = CURRENT_DATE")
```

**NEW code (change `DATE(timestamp) = CURRENT_DATE` to UTC-aware):**
```python
        cur.execute(
            "SELECT COUNT(*) FROM trade_log "
            "WHERE exchange LIKE 'kraken%%' AND action='BUY' "
            "AND DATE(timestamp AT TIME ZONE 'UTC') = "
            "DATE(CURRENT_TIMESTAMP AT TIME ZONE 'UTC')")
```

**Verification:** After the change, manually run in psql:
```sql
-- Old (could be wrong in non-UTC timezone)
SELECT COUNT(*) FROM trade_log 
WHERE exchange LIKE 'kraken%%' AND action='BUY' 
AND DATE(timestamp) = CURRENT_DATE;

-- New (always UTC)
SELECT COUNT(*) FROM trade_log 
WHERE exchange LIKE 'kraken%%' AND action='BUY' 
AND DATE(timestamp AT TIME ZONE 'UTC') = DATE(CURRENT_TIMESTAMP AT TIME ZONE 'UTC');
```
If your DB is in UTC, both return the same count. If not, they differ.

```python
# --- Daily Strategy Integration ---
DAILY_STRATEGY_PATH = os.path.join(ROOT_DIR, "daily_strategy.json")

def load_daily_strategy():
    """Load Market Architect's daily strategy, or None if unavailable/stale."""
    try:
        if os.path.exists(DAILY_STRATEGY_PATH):
            with open(DAILY_STRATEGY_PATH) as f:
                data = json.load(f)
            # Check staleness (allow yesterday for 00:00-06:30 window)
            try:
                import pytz
                athens_tz = pytz.timezone('Europe/Athens')
                today = datetime.now(athens_tz).strftime('%Y-%m-%d')
                yesterday = (datetime.now(athens_tz) - timedelta(days=1)).strftime('%Y-%m-%d')
                date_str = data.get("date", "")
                if date_str not in (today, yesterday):
                    print(f"⚠️ Daily strategy stale (date={date_str}), ignoring", file=sys.stderr)
                    return None
            except ImportError:
                pass  # pytz not available, accept strategy as-is
            return data
    except (json.JSONDecodeError, IOError) as e:
        print(f"⚠️ Could not load daily strategy: {e}", file=sys.stderr)
    return None
```

## Risks

1. **Alpaca entry logic** — the daily strategy integration adds complexity. If focus_pairs is set but no symbols match, no entries will fire. This is correct behavior.
2. **Staleness check** — the `yesterday_athens` fix exposes the AI Overseer to 1-day-old strategies. The 5-min strategies already do this, so it's safe.
3. **Timezone fix** — `timestamp AT TIME ZONE 'UTC'` assumes the stored timestamp is in UTC (which it should be — `TIMESTAMPTZ` with `DEFAULT CURRENT_TIMESTAMP` in PostgreSQL stores as UTC). If timestamps were inserted with local time, this fix would shift boundaries. Verify with a test query first.
4. **Import location** — when adding `json` to alpaca_stocks.py imports, check it's not already imported. If `json` is already used elsewhere in the file, don't add a duplicate import.
